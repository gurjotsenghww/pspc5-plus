# 1080p startup and retained GPU buffers — September 27, 2026

Subnautica: Below Zero now starts its Unity renderer at 1920×1080 with the
default launcher settings. Its main menu shows Play, Options and Credits.
Performance has improved from the earlier 4K run, but the requested 30 FPS
menu target has **not** been reached. Rendering artifacts remain, and this
work does not establish gameplay compatibility.

![Native 1920×1080 menu capture](../images/subnautica-below-zero-menu.png)

The image is an unscaled capture of frame 768 from the final development
build running PPSA02457 v1.022.125. The installed game files were not modified.

## Resolution settings

The launcher already requested a 1080p display mode, but Unity's PS5
`Media/boot.config` independently requested 3840×2160. Resizing the host
window therefore did not reduce the title's render targets.

The selected output resolution now also supplies the supported Unity startup
width and height keys, including the standard-mode variants. The filesystem
exposes a read-only virtual version of that document, with consistent reads,
positional reads, seeks and file sizes. Other settings and line endings are
preserved. Both direct launches and launcher launches use this path; 1080p
remains the default, and explicit resolution choices remain available.

This is an engine-level compatibility path without a Subnautica title-ID
condition. It does not arbitrarily resize every render target in every
engine: other engines, later dynamic resolution changes and prerecorded
movies can still choose different dimensions.

## Repeated uploads and CPU work

- Windows native guest writes now enable the existing GPU page tracker by
  default for all titles. Unchanged ranges retain their buffers; writes,
  protection changes and remapping invalidate reuse through the existing
  generation tracking. Explicit environment overrides still support
  comparisons and troubleshooting.
- The retained buffer cache allows 4096 entries. A 512 MiB device-local
  working-buffer budget is available to every title; it is allocated on
  demand. Small control buffers keep their host backing.
- Cache insertion and replacement update the address index incrementally.
  Shader metadata reads inspect the pending small GPU-written buffers rather
  than scanning every retained allocation.
- Readability checks now agree with the host permissions actually installed
  for write-only guest mappings. Previously, valid GPU descriptor reads took
  the slow `VirtualQuery` fallback. CPU sampling attributed roughly a third
  of the renderer thread's samples to that query before this correction.
  Requested guest protection bits remain unchanged.
- QPC frequency is cached, and the usual integer timestamp conversion avoids
  a 128-bit division on each resource timer.
- Shader resource recovery caches immutable instruction positions. Cache
  identity still includes the program and control-flow graph; guest scalar
  values and memory contents are not cached by this change.

In the measured 1080p menu, page tracking reuses about 26 MiB of buffer data
per frame. Buffer uploads fall from roughly 36 MiB to 14–16 MiB, and buffer
evictions fall from roughly 900 to tens per frame. These are buffer figures,
not all texture/index transfers or all Vulkan submissions. Necessary repeated
draws and dispatches are still executed.

Full-buffer fingerprinting was also measured. It reduced transfers but added
CPU hashing time and did not improve this menu's frame time, so it was not
enabled as the general default. Lowering the device-local size threshold to
16 KiB also made the measured run slower and was rejected.

## Measurements and remaining work

Host: NVIDIA GeForce RTX 3070 Ti, Windows, native x86-64 guest execution and
Vulkan rendering. Frame timings below are sampled emulator frame intervals,
not claims of a constant frame rate. Startup compilation and menu transitions
can be slower.

The September 26 reference menu run at 3840×2160 measured 193–223 ms per
frame, median 204 ms (about 4.9 FPS). The final 180-second ReleaseFast run with
the new 1080p defaults measured **100–121 ms across 20 samples from flips
600–1740, median 105.5 ms (about 9.5 FPS)**. No guest fault or device loss was
reported. Captures were enabled, and their occasional overhead is included.
Before the instruction-position cache, the same 180-second procedure measured
107–130 ms across 18 late samples, median 111.5 ms.

The remaining cost is predominantly the emulator's graphics path. A
representative frame spent about 46 ms inside draw handling and about 28 ms
waiting for GPU completion, with roughly 100 Vulkan submissions. The game
and HLE outside graphics submissions accounted for about 1–3 ms. These
instrumentation categories overlap and must not be added together as an
exclusive CPU/GPU breakdown.

Reaching 30 FPS requires a frame under 33.3 ms. Further work must reduce
resource interpretation and GPU synchronization while preserving buffer
versions and release ordering. The PC edition's 120 FPS does not predict the
performance of the translated console graphics path. The CPU already runs
natively; obtaining the PC edition is not required for these fixes.

To reproduce with the launcher-equivalent performance preference:

```powershell
zig build build-game-run -Doptimize=ReleaseFast
$env:PS5_GAME_PRESET = 'performance'
$env:PS5_INPUT_MODE = 'keyboard'
& .\zig-out\bin\game-run.exe 'E:\PS5 subnautica\eboot.bin'
```

Leave `PS5_OUTPUT_RESOLUTION` unset for the 1080p default. Press Enter at
`Press Options`, allow pipeline warmup to finish, and inspect the `[gpu frame]`
and `[gpu frame split]` diagnostics. The desktop window can fit within the
monitor's work area; its size is separate from the actual 1920×1080 frame.

## Validation scope

- 529 HLE tests, including virtual boot-document behavior and unchanged disk
  content; 22 memory tests, including write-only page readability, tracked
  writes, protection changes and unmapping; 232 GPU tests.
- 182 Vulkan unit tests, plus actual Vulkan probes for deferred shader
  metadata, an expanded buffer cache, queued buffer versions, rename-pool
  pressure and buffer retirement.
- Subnautica title and main-menu runs, with native 1920×1080 captures.
- Cat Quest III opening story at 1920×1080 with readable subtitles, and
  Terminator 2D: No Fate title/menu at 1920×1080. These are short regression
  checks of the shared settings, not new full-game validations.

The remaining supplied titles were not launched for this change. Existing
compatibility milestones for those games have not been re-certified. These
are development changes; the previously published 0.3.2 download predates
them.
